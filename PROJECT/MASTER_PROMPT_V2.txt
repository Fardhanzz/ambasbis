==================================================
0. PRIMARY OBJECTIVE
==================================================

Build TASKORA as a real multi-user web application.

The core experience is:

CAPTURE
→ ORGANIZE
→ PRIORITIZE
→ ACT
→ COMPLETE

The application should solve a simple but important student problem:

"I have too many assignments and deadlines, and I keep forgetting what I need to do."

TASKORA should answer:

"What do I need to do right now?"

The application must therefore prioritize:

TODAY
URGENT
UPCOMING

over overwhelming users with unnecessary information.

==================================================
12. AUTHORIZATION
==================================================

This is critical.

Every user-owned record must belong to the authenticated user.

Conceptually:

User
│
├── Subjects
│
├── Tasks
│   └── Subtasks
│
└── Reminders

User A must never be able to access User B's data.

This must be enforced at the server/database layer.

Do NOT rely only on frontend checks.

Never trust a userId sent by the client.

Resolve the authenticated user from the actual session.

Where supported, use row-level security or equivalent database-level authorization.

==================================================

The following must survive:

- page refresh
- browser restart

- another supported device using the same account

- subjects

- status
- priority
- deadlines
- estimated duration
- notification preferences
- reminders

localStorage may be used for:

- UI preferences
- temporary drafts
- harmless client settings

But NEVER use localStorage as the authoritative database for tasks.
